# edit: SSOS-9 用エディタ

`source ~/.elf2x68k && make -C apps/edit` で `build/edit.s9m` と、読み込み用 2HD イメージ `build/edit.xdf` を生成する。SSOS-9 で FAT16 を `smount` し、ドライブ 1 に `edit.xdf` を挿入して `load 1 EDIT.S9M`、`mux`、`run edit SOURCE.S` を実行する。ファイル名は FAT16 ルートの ASCII 8.3 形式。`run` は空白区切りで引数を渡し、引用やエスケープは未対応。

- 通常モード: `h` / `j` / `k` / `l` で移動、`i` で挿入、`a` で次の位置に挿入、`x` で削除、`:` でコマンド入力。
- 挿入モード: ASCII、Tab、改行を挿入。Backspace は直前のバイトを削除し、Escape で通常モードへ戻る。
- コマンド: `:w` 保存、`:q` 変更がなければ終了、`:q!` 変更を破棄、`:wq` 保存して終了。各コマンドの後に Return を押す。
- ファイル上限は 16384 byte。画面には 23 行を表示し、長い行は水平にスクロールする。Tab や ASCII 以外のバイトは空白で表示するが、保存時は保持する。カーソル移動・削除の単位はバイトであり、日本語文字の編集には対応しない。

読み込みエラー時は新規作成の確認を表示する。`n` は空の編集バッファを開き、`q` は終了する。新規保存時は既存ファイルを上書きしないため、I/O エラーで既存ファイルを読み込めなかった場合も保存は失敗する。編集済み表示は `*`。保存失敗時は画面に原因の段階を表示し、変更状態とバッファを保持する。容量超過では挿入を拒否する。`:q!` と Ctrl-C は未保存の変更を破棄する。

検証済み: ホストテストで編集・保存・失敗動作を確認し、QEMU では実際の S9M1 を実行して FAT16 ファイルの新規作成・再編集・置換保存を確認した。QEMU での mux 切替はテスト API から行っており、実キー入力による切替確認ではない。更新後の Human68k 起動イメージを MPX68K で起動し、エディタ編集中の `~2` → `~1` 切替と未保存内容の保持を確認済み。MPX68K 上の FAT16 保存・再読込は未確認。

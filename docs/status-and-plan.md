# 開発状況と今後のプラン

更新日: 2026-11-11

## 目的と範囲

SSOS-9 上で、複数のシェル画面を切り替えながらエディタでソースを編集し、アセンブラとリンカでビルドし、別画面で実行を確認する。Human68k `.x` の互換実行は必要としない。C コンパイラとプリプロセッサは後回しにする。既存の preemptive scheduler と CLI を基盤とする。

## 現在の Status

| 項目 | 状態と制約 |
| --- | --- |
| 起動とプロセス | Timer D による preemptive scheduler、process、S9M1 module、限定的な C Hello と外部 module の読み込みを実装済み。汎用 C runtime は未実装。 |
| FAT12 | 2HD の MS-DOS 型 FAT12 ルートから 8.3 名の module を読み込む。Human68k 固有形式の互換性は未検証。 |
| FAT16 | SCSI 上の FAT16 を最大 2 GB まで扱う。ASCII 8.3 ルート名、全体転送は最大 65536 byte、ファイル記述子の逐次読み書きは対応済み。`smount` の開始位置と任意の範囲長は明示指定で、パーティション自動検出はない。書き込みマウント時に FAT 複製の一致を検査する。 |
| 多重画面 | `mux` で 3 シェルを起動し、画面・キー入力・foreground process を分離。`~` と数字、F1～F3、または Ctrl-] と数字で切り替える。80×25 の文字画面で、汎用端末制御や画面分割は未実装。 |
| 開発ツール | エディタ、ターゲット上で動くアセンブラとリンカは未実装。ファイル記述子による段階的な読み書きを実装済み。対話アプリ向けの入力 ABI、リダイレクトは未実装。 |

## 検証状況

- `source ~/.elf2x68k && make verify` は 2026-11-11 に成功。クロスビルド、ホストテスト、QEMU テストを含む。QEMU のディスク・IOCS は代役であり、実機の割り込みや IOCS 動作の検証ではない。
- XEiJ 0.26.10.08、MC68000、12 MiB、Human68k 3.02 の HDD 起動で、専用 32 MiB FAT16 イメージの SCSI IOCS 経由マウント、新規作成、読み戻し、置換を確認。停止後に `mtype` と `fsck.fat -n` でも確認した。
- MPX68K で `~` と数字による切り替えと画面保持、XEiJ で F1～F3 による切り替えと画面保持を確認。XEiJ では制御パイプでキー入力し、ユーザーがコピーした画面内容で確認した。
- MPX68K の macOS 入力処理に Ctrl 状態の転送を追加した検証版で、Ctrl-C による入力行破棄と `run counter` の中断、Ctrl-] と数字による 3 画面の切り替え・表示保持を確認した。検証版は別途ビルドしたアプリであり、インストール済みの MPX68K への反映は別途必要。
- ストレージのホスト試験に 512／1024 byte セクタ、FAT 複製の不一致、範囲外の BPB、書き込み故障時のフェンスを追加した。これらを含む変更後の IOCS 経路はエミュレータ未検証。
- 2 GB の疎 FAT16 イメージで作成、逐次書き込み、読み戻し、`fsck.fat -n` をホスト上で確認。MPX68K は追加 HDD を接続できないため、変更後の IOCS 経路は未確認として受け入れた。
- 実機・実媒体、全 FAT16 ジオメトリ、電断や I/O エラー時の整合性、実キーボードの全操作は未検証。検証環境と成果物ハッシュは [tests/README.md](../tests/README.md) を参照。

## 今後のプラン

### Phase 1: 入力・ストレージ基盤

1. MPX68K の Ctrl 入力修正を通常の利用環境へ反映し、実キーボードや必要な配列で Ctrl-C と Ctrl-] を確認する。検証版での動作確認は完了済み。
2. 対話アプリ向けのキー入力・カーソル移動・画面消去と、各 mux 画面への入出力の契約を定める。長時間動作中の画面切り替えとバックグラウンド出力も確認する。
3. エディタと開発ツール向けのファイル API を実装。ファイル記述子、段階的な読み書き、置換、エラー、排他の契約を定義済み。
4. FAT16 の書き込み失敗、空き領域不足、FAT 複製、512／1024 byte セクタ、2 GB イメージをホスト・QEMU と外部 FAT ツールで検証し、障害対応を明文化済み。[現行契約と障害時の扱い](storage-contract.md)を参照。MPX68K では複数 HDD を接続できないため、更新後の IOCS 実操作は未検証。

完了条件: mux 内で対話プログラムの入力・表示・中断が安定し、ツールが必要とするファイルを作成・読み書きできる。既存テストに加え、X68000 対応エミュレータで入出力を確認する。

### Phase 2: vi に似たエディタ

1. 表示・カーソル移動・挿入・削除・保存・終了を持つ小さなエディタを S9M1 アプリとして実装する。
2. ファイル読み込み、変更状態、保存失敗の通知、領域不足時の挙動を定義する。操作範囲とファイルサイズ上限を明記する。
3. mux の一画面で編集し、別画面へ切り替えて戻った後も編集内容と画面を保つことを検証する。

完了条件: FAT16 上のアセンブリソースを新規作成・編集・保存・再読込でき、mux 切り替え後も作業を継続できる。

### Phase 3: 68000 アセンブラ

1. 対象を MC68000 とし、構文、命令・アドレッシングモード、シンボル、式、疑似命令、エラー表示を定義する。最初にサポート範囲を明示し、未対応を黙って受理しない。
2. リンカ向けのオブジェクト形式と relocation の契約を定め、複数ファイルを扱うための二段階アセンブルを実装する。
3. 既知の命令エンコーディングとエラーケースをクロスツールチェーンと比較し、ターゲット上でも実行する。

完了条件: エディタで保存した複数のソースから、定義済みオブジェクト形式を生成できる。

### Phase 4: リンカと実行確認

1. セクション配置、シンボル解決、relocation、未解決・重複シンボルの診断を実装する。S9M1 の既存 loader・PIC/A5 契約に合う出力形式を設計する。
2. 複数オブジェクトを結合して実行可能 module を作り、既存 loader で起動・終了・回収する。
3. 一画面で編集、別画面でアセンブル・リンク、第三画面で実行する一連の操作を FAT16 上で検証する。

完了条件: 外部ホストのアセンブラやリンカに依存せず、対象のアセンブリプログラムを作成から実行まで通せる。

### 後続: C コンパイラとプリプロセッサ

上記の実行・ファイル・オブジェクト契約が安定してから設計・実装する。C の対象範囲、ランタイム、ライブラリ、ABI とセルフホストの要否はその時点で決める。

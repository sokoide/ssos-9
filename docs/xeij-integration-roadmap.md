# XEiJ統合テストの安定化・高速化・カバレッジ拡張計画

2026-11-18。対象はSSOS-9のサポート済み動作と、障害時に仕様で定義された挙動。ホストのunit／integration testで完結する契約はそこで検証し、QEMUで検証済みのCPU・カーネル契約はその証拠を再利用する。XEiJではX68000の起動、MFP、IOCS、画面・キー入力、仮想媒体とゲストを結合した経路を検証する。物理キーボード、実ドライブ、実機タイミングなどは実機の確認項目として追跡する。

## 現状

現行の `make test-emulator-list` は25 IDを列挙する。既定の15ケースに加え、媒体書込み・専用fixtureを要するケースがある。c4はF1/F2/F3経路でPASS。FD1のh2はXEiJの自動化対象外とし、MPX68Kで手動PASSを確認した。IPL再起動を伴う `a3` と `h5` は共通処理の候補。

- ケースと操作手順は [既存統合テスト計画](emulator-integration-test-plan.md)、[リモート操作手順](emulator-remote-operation.md)、[現行ランナー](../tools/emulator-itest.sh) を参照。
- 検証層と過去の測定値は [テスト一覧](../tests/README.md)、[前回のカバレッジ・高速化計画](test-coverage-and-speedup-plan.md) を参照。

## 1. 再現性と失敗診断

1. 固定したXEiJ/JVM・ROM・Human68k・機種・CPUクロック・RAM構成を用意する。ROMと媒体の配布条件に従い、ローカルのベース画像を実行ごとに複製する。専用ini、HFS公開先、FIFOの所有プロセスを起動時に照合する。FIFO、画面キャプチャ、クリップボードを共有する構成ではホスト単位の排他を取る。既存のユーザーセッションは専用環境の起動・終了・復旧試験から切り離す。
2. ランナーに起動、キー入力、画面取得、待機、媒体接続、復旧の境界を設ける。単調時計の期限を設定し、FIFOに読者がいない場合も書込みが有限時間で戻るようにする。修飾キーはエラー経路でも解放する。通常終了、失敗、INT/TERMをテストし、強制終了後は次回の起動前に所有情報を照合して孤立セッションを回収する。
3. 画面コピーの成功とコマンド完了を別々に確認する。前者はクリップボードの更新を、後者は新しいプロンプトと期待出力の順序、固有名、PID、画面番号などを使って判定する。同じ画面を得た場合も古い出力が条件を満たさないようにする。前面アプリの割込みなどで再取得する場合は期限内の観測に限る。書込みやプロセス起動は結果不明のまま再送しない。
4. ケース単位でPASS、製品の期待値不一致、環境／搬送エラー、未実行を記録する。必須ケースに未実行があればフルスイートを不合格にする。初回結果と診断目的の再実行は両方保存する。実行環境と成果物のハッシュ、ステップ別時間、末尾画面、送信履歴、媒体差分、復旧結果を保存する。古い画面、FIFO消失、権限不足、途中終了の扱いは偽の搬送層でホストテストする。

## 2. 高速化

| 順序 | 変更 | 採用条件 |
| --- | --- | --- |
| 1 | ビルド、起動、fixture配置、入力、画面取得、ゲスト待ち、終了・画像検査を別々に計測する | 同じホスト・成果物・ケース集合で変更前後の中央値とp95、失敗件数を比較できる |
| 2 | 既存の適応ポーリングを残し、残存する固定待機をプロンプト、PID、媒体準備完了などの観測に置き換える | 遅延したゲストと古い画面を注入しても誤合格しない。キーごとの待ちとTimer測定窓は別に扱う |
| 3 | 成果物を一度だけ用意し、同じ起動方式・媒体構成のケースをまとめる。a3/h5のIPL準備を共有する | 各ケースの開始時にプロンプト・mux・残存タスク・FD・媒体を確認でき、単独実行と一括実行で同じ判定になる |
| 4 | fixtureをホストで事前構築し、キー入力が検証対象の編集操作だけを実際に入力する。高速入力やGUI非依存の画面取得は固定XEiJ版で試作する | 文字列・修飾キー・画面行・タイミングの同等性を従来経路と比較できる。経路が成立しなければ現行搬送を使う |

ケース後の状態確認に失敗したらセッションを隔離し、新しい複製で後続を実施する。媒体書込みテストはケースごとに初期画像を復元するか、ケース専用画像を使用する。独立したディスプレイ、FIFO、クリップボード、媒体を割り当てられるまでは逐次実行する。

## 3. XEiJで閉じる検証項目

以下を起点として、実装時に起動入口、ハードウェアアクセス箇所、媒体・機種の対応表をソースから棚卸しする。各行をサポート契約、対象コード、ケースID、入力、合否条件、証跡に結び付ける。既存ケースは項目ごとに判定を照合し、ケース名だけでカバー済みと判定しない。

| 境界 | 既存ID | 追加・強化する判定 |
| --- | --- | --- |
| Human68k起動と復帰、XDF IPL | a2、a3、h5 | 同じHuman68kセッションで起動・終了を反復し、終了後に入力とディスクアクセスを確認。デバッガ等でTimer Dの所有レジスタとベクタを起動前後に採取し復元を比較。IPLではPID 1の終了拒否後も操作可能であることを確認 |
| MFP Timer Dと実割込み | b1–b4、f1、g1、h6 | 単調時計でtick増分を測定し、固定プロファイルで200 Hzの許容範囲を適用。CPU占有中に別タスクと入力が進むことを観測し、連続切替後にタスク・arenaが基準へ戻ることを確認 |
| IOCS入力・画面・mux | c1–c5、f2、h3 | 実キー入力のコード、修飾キー、Ctrl-C配送先、長い出力と各画面の再描画を確認。mux切替はF1/F2/F3で確認する。`~1`〜`~3` と Ctrl-]+数字はXEiJのIOCS入力経路で正しく届かないため、XEiJの自動化では用いない |
| IOCSフロッピー・FAT12 | 対象外 (MPX68K手動) | MPX68K FDD GUIでFD1へ専用画像を挿入し、Human68k C:からSSOS-9を起動。`load 1` と実モジュール起動を確認。手順・ハッシュは `tests/README.md` |
| IOCS SCSI・Human68k形式HDD | d1–d4、h4、h5 | 専用複製で作成・上書き・読出しを行い、ゲスト停止後にホストから内容と対象外ファイルを照合。別パーティションを保全すること、未接続または未対応媒体で拒否することを確認。対応する両起動経路を通す |
| 実画面・実媒体を伴うアプリ通し | d2–d4、e1–e3、f2 | 実キー操作で編集・保存・再読込し、asm/ldの出力をホストの期待バイト列と照合。ディスクfallbackで起動したプログラムの出力を確認。未定義シンボルでは出力が生成されずシェルが継続することを判定 |

c4は専用XEiJプロファイルでF1/F2/F3を使った自動試験がPASS。h2はMPX68KのGUI挿入で手動PASS。XEiJはFD媒体の差し替え動作が不安定なため、h2はXEiJ自動化の完了条件から外し、MPX68K手順を回帰証跡として維持する。物理機固有の項目は環境と実機手順を台帳に残す。

## 4. 実装順序と完了条件

1. **基準測定** — 既存25 XEiJ IDとMPX68K手動H2の状態、ケース別所要時間、個別の未解決理由を記録する。代表ケースは `a2 a3 b1 c3 d2 e1 h5`。
2. **安定化** — 専用環境、期限付き搬送、観測の鮮度判定、終了時の保全を実装する。失敗注入で回収を確認する。
3. **未到達経路の解消** — c4のFキー経路を維持し、h2はMPX68K手動試験で管理する。MFP復元の直接観測を優先する。カバレッジ台帳をコード・既存テストと照合し、残りの不足を追加する。
4. **性能改善と運用** — 固定待機を削減し、媒体構成ごとに実行をまとめる。既存のID選択を維持し、通常の短い回帰、全経路を通るフル、反復するソークを明示する。ホスト／QEMUの `make verify` は独立して実行できるようにする。

リリース判定の提案値は以下のとおり。性能は基準測定後に確定する。

- 短い回帰を30回、フルを10回、初回試行で連続合格。ソークで25回の起動・停止・回収サイクルを通し、arenaとタスクの基準値を毎回確認する。**未達**: h6の25サイクルは合格したが、短い回帰30回・フル10回の連続実行は未実施。
- 同じケース集合で総時間の中央値を短い回帰で20%以上、フルで30%以上短縮し、p95が悪化しない。起動を含む測定とセッション再利用の測定は別々に報告する。**未達**: 現状はa2の各1回比較とd1単発比較のみで、中央値・p95と短縮率は未測定。
- サポート範囲にあるXEiJ固有の各項目に自動ケースと合格証跡がある。XEiJ自動化対象は自動ケースで合格し、XEiJ外のh2は指定したMPX68K手順で合格すること。
- ベース画像とユーザー設定のハッシュ、実行前後のプロセス状態を確認する。正常時と異常終了時のいずれも専用資源を回収できる。ホスト、QEMU、XEiJ、実機の結果を個別に記録する。

計画の策定時にはリポジトリ内の資料、ランナー、ケース一覧を照合した。実装後の結果を以下に記録する。

## 2026-11-18 実装・検証記録

- 制御FIFOの期限付き送信、macOSの画面取得コマンドの期限、同一ユーザーの排他、対象のPID指定、強制終了で残った設定バックアップの検出を追加した。文字キーのみのコマンドは、キー間隔0.1秒を保ったまま1プロセスで送る。修飾キーを押したままTERMを受けたケースもホストで検証する。
- 専用ini・HFS・複製媒体を作成し、スイートごとにランナーのコピー、初回判定、ケース時間、キー履歴、最後の画面、設定と媒体のハッシュを記録する。操作とプローブの起動は [エミュレータ操作手順](emulator-remote-operation.md) を参照。
- XEiJ 0.26.10.08、Human68k 3.02、MC68000、12 MiBで `a3` と `h5` のIPL・PID 1保護・ini復元が合格。プローブ付き `a2` は、IERB・IMRB・TCDCR・停止中のTDDRとTimer D・TRAP #0・#13ベクタの一致を5回確認した。
- `d1` の媒体には最初の空きクラスタまで9,154個の既使用エントリがあり、同じFATセクタを繰り返し読んでいた。探索で読み取ったセクタを再利用し、旧実装と修正版でそれぞれ140.32秒、114.06秒を観測した。単発の比較であり、中央値・p95は未集計。旧実装ではホストの読出し回数回帰が失敗することも確認した。
- `c4` はF1/F2/F3で自動PASS。`h2` はMPX68KのFD1 GUI挿入で手動PASS。FD1はHuman68k上でC:として認識された。
- `e1` の初回は、3ソースの編集・保存後、muxのウィンドウ2で最初のasmを起動したところでアドレスエラーになった。異常時PCの命令は `ss_do_wakeups` に対応する。FATファイル読出しでセクタ用の1 KiBバッファを二重に確保していたため、ディレクトリ・データ読出しとチェーン追跡で同じ作業領域を使うよう修正した。クロスコンパイラのスタック使用量では、チェーン追跡のフレームが1,076バイトから48バイトになった。修正後のXEiJ再実行では、3画面の編集→asm→ld→run、出力 `lnk`、終了コード27、arena復帰、成果物の削除まで合格した。
- 修正版の専用プロファイルで `d1`〜`d4`、`e2`、`c5`、`f2`、`h4` が合格。停止後のHDDから `D1TD47CD.TXT` の `world` と対象パーティション外の一致を確認した。元のiniと3個のHDD、書込み対象外の複製HDD2個は実行前後でハッシュが一致した。未接続SCSI ID 6のマウント拒否も確認した。
- 自動回帰の24 IDは複数の専用プロファイルとビルドに分けて合格を確認した。最新の `h6` は25回すべてで対象PIDを回収し、直後のarenaを照合した。この時点では同じビルドでの全ケース連続実行と、30回／10回の反復測定が未実施だった。証跡は `build/xeij/results/2026-11-18-sol/`。
- 旧・新ランナーで同じアプリ・プロファイル・`ssos9.x` を使った `a2` は74.44秒→64.85秒。追加のMFPプローブは外し、各1回を比較した。
- 現行ビルドの初回連続ランは `a2`、`a3`、`b1`、`b2` が合格し、`b3` の回収で中断した。FIFO送信は `wait 2`、ゲストの入力エコーは `fwafitr e2`。混入元は未特定。入力の不一致を誤ったコマンドの実行前に検出するため、`b3` の `kill`・`wait` はEnter前に入力エコーを照合する。失敗記録は `build/xeij/results/tmpunluh49s/`。
- 2回目の連続ランでは `b3` の `kill 2` を送信後、画面に `kill` まで表示された段階で照合が停止した。意図したコマンドの先頭と一致する途中のエコーは期限まで待ち、異なる文字列はEnter前にエラーとする。ホストテスト10件と専用XEiJの `b3` 3連続が合格した（`build/xeij/results/tmpzhqxxubb/`）。修正版の全24ケースは `build/xeij/results/tmp5pz5nvhh/` に記録した。
- 自動24ケースの起動前に、専用iniの媒体・HFS指定を複製台帳と照合する。元画像への差し戻し、元画像との同一inode、専用領域外の共有指定を検出した場合は、ケースを起動せずに終了する。専用XEiJのiniで照合が通り、元画像を指すiniをホストテストで拒否することを確認した。
- 現行ビルド・同一専用プロファイルでの `make test-emulator-automated` は24/24、終了コード0、総時間2,285.30秒。元ini・元HDD・書込対象外の複製HDDは実行前後でハッシュが一致した。XEiJ終了後、対象ファイルの内容 `world` と対象パーティション外の一致を再確認した。証跡は `build/xeij/results/2026-11-18-sol/full-24/` と `d1-full-offline.log`。最終 `make verify` も合格した。リリース判定の提案値（30回／10回、総時間の中央値・p95）は未測定。

- 追加確認: 専用XEiJプロファイルの `c4` はF1/F2/F3でPASSし、画面2の `mem` と画面3の `ps`、F1復帰時の表示保持を確認。画面バナーは `Multiplexer: F1/F2/F3 or Ctrl-] and a digit to switch windows.`。

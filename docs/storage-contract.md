# ストレージの現行契約と障害時の扱い

## マウントと境界

`smount ID [START [BLOCKS]]` は SCSI ターゲットの物理ブロックを使う。`START` の省略値は 0、`BLOCKS` の省略時は開始位置からデバイス末尾まで。指定範囲内の Human68k SCSI ディスク識別子、パーティション表と先頭パーティションの BPB を検査する。範囲外・重複するパーティションや MS-DOS 型 HDD は拒否する。ディスクの先頭パーティションだけを扱い、Human68k のドライブ文字と SCSI ID の対応は自動検出しない。

Human68k の論理セクタは 1024 byte、SCSI 物理ブロックは 512 または 1024 byte。512 byte の場合は 2 ブロックを組み合わせる。BPB の総セクタ数がパーティション範囲を超える場合は拒否する。Human68k 用 FAT のバイト順は BPB に従い、第 1 FAT を更新する。FAT12 の読み取り専用 module loader は別経路。

## ファイルと排他

現行のアプリ向け API は `ss9_file_load` と `ss9_file_store` であり、ASCII 8.3 ファイル全体を最大 65536 byte で扱う。既存のサブディレクトリを `TEST/FILE.TXT` や `A:\TEST\FILE.TXT` で指定できる。最大 16 階層、パス全体は終端込み 64 byte 以下。`A:` は選択済みパーティションを指し実際の Human68k ドライブ対応は検証しない。8.3 名の照合は大文字小文字を区別しない (Human68k は作成時のケースのまま保存し、自身の検索もケース無視である)。SSOS-9 が作成する名前は大文字で格納される。ディレクトリ作成・拡張、18+3 名と Shift-JIS は未対応。作成は既存名を拒否し、置換は既存の通常ファイルのみを対象にする。置換時は新しいクラスタ列へ書いた後でディレクトリ項目を切り替え、旧クラスタ列を解放する。空き容量不足や不正名は拒否する。
Human68k拡張名は対応範囲外。Human68k 3.02生成媒体では、9文字目以降はディレクトリエントリの `0x0C` から始まる。ASCII 8.3検索ではこの継続部分を持つエントリを除外する。`0x0C–0x0D` の低値メタデータ (< `0x20`) は従来どおり許容する。

作成時刻の設定は未対応。ディレクトリの終端項目がセクタ境界にある場合は、後続セクタがあれば終端を移してから新しい項目を公開する。

読み取りは `ss9_open_read`、`ss9_read`、`ss9_close` でも行える。記述子はプロセスごとに 3〜10、全プロセスで最大 16 個。読み取り位置は各記述子で独立し、終了時に解放される。`ss9_read` は一度に最大 65536 byte、EOF では 0、エラーでは負値を返す。読み取りエラー時は位置を進めないが、出力バッファの一部が変更される場合がある。

`ss9_open` の `SS9_OPEN_CREATE` または `SS9_OPEN_REPLACE` と `ss9_write` で段階的に書き込める。各書き込みは最大 65536 byte。新しいクラスタ列は `ss9_close` が成功するまで対象名に公開されず、プロセス終了時は中止して解放を試みる。書き込み失敗時には記述子を閉じ、空き容量不足なら未公開クラスタを解放する。I/O エラーや解放失敗では媒体をフェンスする。電断や I/O エラーで未使用クラスタが残る可能性があり、トランザクション保証はない。

システムのストレージ操作は IOCS lock で直列化される。読み取り記述子が開いている間はボリューム全体への書き込みを拒否し、書き込み記述子を開いている間は別の記述子の open と更新を拒否する。いずれかが開いている間はアンマウントを拒否する。seek と append は未実装。記述子はホストと QEMU の模擬 IOCS で検証した。MPX68K では追加 HDD を接続できないため、変更後の IOCS 実操作は未検証。

## I/O エラー後

ファイル更新中に I/O エラー、または書き込み開始後の失敗が起きた場合、以後の書き込みを拒否する。媒体には未使用クラスタの残存や FAT 複製の不一致が残る可能性がある。失敗が報告されても物理書き込みが完了している可能性があり、直前の内容へ戻ったと仮定しない。

1. 当該媒体への書き込みを停止し、エミュレータまたは機器から安全に取り外す。
2. 元イメージを保全し、解析・修復はコピー上で行う。
3. Human68k 形式に対応したツールで読み取り専用の検査を行い、第 1 FAT、クラスタチェーン、対象ファイルの内容を確認する。`fsck.fat -n` を Human68k 固有形式の検査手段と仮定しない。
4. 必要な復旧・修復と再検査の後にのみ、媒体を再利用する。単にアンマウント・再マウントしてフェンスを解除することは整合性確認の代わりにならない。

現行実装には power-fail injection や実機媒体による回復検証はない。ホスト試験で確認したセクタサイズ、複製不一致、故障注入は [tests/README.md](../tests/README.md) を参照。

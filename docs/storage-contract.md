# ストレージの現行契約と障害時の扱い

## マウントと境界

`smount ID [START [BLOCKS]]` は SCSI ターゲットの物理ブロックを使う。`START` の省略値は 0、`BLOCKS` の省略時は開始位置からデバイス末尾まで。`BLOCKS` を指定する場合は正の数とし、開始位置とブロック数がデバイス容量を超える場合は拒否する。パーティション表は自動解析しない。パーティションを扱う場合は、正しい開始位置と長さを別途確認して指定する。

FAT の論理セクタと SCSI 物理ブロックはともに 512 または 1024 byte で、サイズが一致する必要がある。BPB の総セクタ数が指定範囲を超える場合は拒否する。書き込み可能な FAT16 マウントでは、全 FAT 複製を比較し、一致しない場合や読み込みエラーの場合はマウントを拒否する。FAT12 の読み取り専用 module loader は別経路。

## ファイルと排他

現行のアプリ向け API は `ss9_file_load` と `ss9_file_store` であり、ルートの ASCII 8.3 ファイル全体を最大 65536 byte で扱う。作成は既存名を拒否し、置換は既存の通常ファイルのみを対象にする。置換時は新しいクラスタ列へ書いた後でディレクトリ項目を切り替え、旧クラスタ列を解放する。空き容量不足や不正名は書き込み前に拒否する。

システムのストレージ操作は IOCS lock で直列化される。読み取り用ファイル記述子と段階的な読み取りは実装途中であり、契約と専用テストが未完成。段階的な書き込み、seek、append は未実装。異常終了や電断に対するトランザクション保証はない。

## I/O エラー後

ファイル更新中に I/O エラー、または書き込み開始後の失敗が起きた場合、以後の書き込みを拒否する。媒体には未使用クラスタの残存や FAT 複製の不一致が残る可能性がある。失敗が報告されても物理書き込みが完了している可能性があり、直前の内容へ戻ったと仮定しない。

1. 当該媒体への書き込みを停止し、エミュレータまたは機器から安全に取り外す。
2. 元イメージを保全し、解析・修復はコピー上で行う。
3. フォーマットに対応したツールで読み取り専用の検査を行い、FAT 複製、クラスタチェーン、対象ファイルの内容を確認する。`fsck.fat -n` は対応する MS-DOS 型 FAT イメージに対する検査例であり、Human68k 固有形式全般の修復を保証しない。
4. 必要な復旧・修復と再検査の後にのみ、媒体を再利用する。単にアンマウント・再マウントしてフェンスを解除することは整合性確認の代わりにならない。

現行実装には power-fail injection や実機媒体による回復検証はない。ホスト試験で確認したセクタサイズ、複製不一致、故障注入は [tests/README.md](../tests/README.md) を参照。
